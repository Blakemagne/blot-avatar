An avatar with a body

Eyes on a real 3D shape, drawn as three SVG paths.

Pick one, colour it, set it to work. Or describe your own to any model and bring back what it draws: an outline and two eyes become a body.

Your system asks for reduced motion, so every avatar here is a still picture, facing front: moves, faces, activities and following are not shown.

Move your pointer. Click it. Keys 1 to 6 pick what it does.

What it is like to move

The engine's own feel is weight, squash and wobble at 0.5, flare and float at 0. Try a hop, a bounce or a recoil.

Your page

Moves are data

A move is written in plain words: a part of the avatar, what it does, how far, and the shape it takes over the move. These cards are built from the package's list of moves, so a new one shows up here by itself. The last one, the waggle, is not in the package at all: this page writes it in three lines and brings it in through the clips option.

    The waggle, written on this page
    import { mount } from '@blot/avatar';
import { cue, eyes, head, toward, wave } from '@blot/avatar/moves';

// A waggle: a swing and a half from side to side, dying away, the eyes going with it.
const waggle = cue(900, [
  head.lean(toward, 7).along(wave(1.5).dwindling()),
  eyes.glance(toward, 0.15).along(wave(1.5).dwindling()),
]);

const bot = mount(el, { shape: 'heart', size: 96, clips: { waggle } });
bot.play('waggle', { dir: -1 });

    Every body

    Each body the engine draws, all watching your pointer on one shared frame loop. Click one to poke it, or try it in the studio.

      At every size

      One under 48 px is drawn at most 30 times a second and turns only part of the way, so a small one keeps its face. One of 64 px and up takes a full look.

        Put one on your page

        Any page, no framework
        import { mount } from '@blot/avatar';

const bot = mount(document.getElementById('bot'), {
  shape: 'heart', size: 96, color: 'tomato', eyeFill: '#FFF4D6',
  follow: true, pokeable: true, label: 'Ada',
});

bot.play('bounce');
bot.update({ activity: 'thinking', face: 'attentive' });
bot.destroy(); // the element is left as it was found
        React
        import { useLiveAvatar } from '@blot/avatar/react';
import { svgBox } from '@blot/avatar';

export function Avatar({ size = 72 }) {
  const { host, paths, first } = useLiveAvatar({ shape: 'star', size, follow: true });
  const box = svgBox(size);
  return (
    <span ref={host} style={{ position: 'relative', display: 'inline-block', width: size, height: size }}>
      <svg width={box.width} height={box.height} viewBox={box.viewBox} aria-hidden
        style={{ position: 'absolute', left: box.left, top: box.top, overflow: 'visible' }}>
        <path ref={paths[0]} d={first.body} fill="#FD690F" />
        <path ref={paths[1]} d={first.eyes[0]} fill="#fff" />
        <path ref={paths[2]} d={first.eyes[1]} fill="#fff" />
      </svg>
    </span>
  );
}

        What it promises

        • One frame loop. However many avatars a page has, they share one requestAnimationFrame.
        • Nothing drawn that nobody sees. Off screen, in a hidden tab or at rest, an avatar costs nothing.
        • Reduced motion respected. Under it every avatar is a still picture and moves do nothing.
        • Deterministic. The same seed and the same steps draw the same paths, bit for bit. A frozen hash of every frame guards that.
        • Paths, not pixels. Each frame is three SVG path strings, the body and two eyes. Colour each with any CSS: color for the body, eyeFill for the eyes.
